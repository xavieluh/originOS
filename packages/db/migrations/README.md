Generated by drizzle-kit (`pnpm --filter @originos/db db:generate`), plus hand-written SQL migrations created with `drizzle-kit generate --custom` (row-level security, roles). Never edit a migration after it has been applied anywhere; add a new one.

## Rolling back (development and test only)

Every migration has a reverse script in `down/<tag>.sql` (Phase 06, ADR-025). Add one with each new migration, in the same PR. `pnpm --filter @originos/db rollback -- <steps> --destroy-data` undoes the newest `<steps>` applied migrations, each in one transaction, and removes them from drizzle's journal so `pnpm db:migrate` re-applies them. It refuses `NODE_ENV=production` and destroys the data those migrations hold. Roles (`originos_app`, `originos_worker`) are cluster-wide and are kept. `test/integration/rollback.test.ts` runs every migration down and up on a throwaway database and checks the schema comes back identical.

Production never rolls back by script: a bad migration is fixed with a new forward migration.
